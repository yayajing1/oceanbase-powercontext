# 研读台 PaperDesk — 需求说明书（PRD）

> 这是交给 Qoder 的**任务书**。技术设计（模块划分、数据模型、接口）由 Qoder 在
> 「需求拆解」环节提出，本文件只规定**要解决什么问题**、**必须做到什么**、
> **怎么算完成**。

---

## 1. 背景与真实痛点

研究生 / 科研工作者读文献时，反复遇到三件事：

1. **找不到**：读过几十篇论文，笔记散在本地文件夹、聊天记录、Word 里；
   三周后想找"那篇用了对比学习的图注意���方法"，要翻十几个文件。
2. **记不住**：读过的论文没有结构化沉淀，半年后只记得"好像挺重要的"。
3. **写不出**：写开题报告 / 综述时，要重新回忆每篇文献的贡献，
   而不是从卡片库里挑。

**研读台（PaperDesk）** 要做的就是：把本地文献笔记变成一个**可检索、可沉淀、
会记住你**的本地研究工作台。

---

## 2. 目标用户与使用场景

| 用户 | 场景 |
| --- | --- |
| 研一/研二学生 | 每周导入 3~5 篇论文笔记（Markdown），做检索与卡片 |
| 写开题报告的人 | 按标签/年份聚合卡片，生成综述提纲初稿 |
| 组会分享者 | 把卡片整理成组会汇报提纲 |

**核心场景（必须完整跑通）**：导入笔记 → 检索到相关片段 → 生成研究卡片 →
复习卡片并记录掌握度 → 下次运行时系统"记得"我的画像与复习进度。

---

## 3. 功能需求

### F1 文献导入

- 批量导入 Markdown / 纯文本文献笔记。
- 自动切块：按 Markdown 标题层级切分；没有标题时按段落切分，单块不超过 N 字符
  （N 可配置，默认 800）。
- 解析并保存元数据：标题、作者、年份、标签、来源文件、块在文件中的行号区间。
- **幂等**：同一文件重复导入不产生重复块；文件内容变化时，被删除的旧块必须消失。

### F2 混合检索

一个查询同时使用**两类能力**：

- **关键词全文检索**：在 seekdb 的原生全文索引上做匹配，中文必须能命中。
- **结构化条件过滤**：年份区间、标签（可多选，OR）、作者。

返回结果必须包含：**片段正文 + 出处（来源文件 + 行号区间）+ 相关度分数**，
并标明是被全文命中还是被结构化条件命中。

### F3 研究卡片

- 对选中的片段生成一张研究卡片，字段固定为：
  `问题 / 方法 / 结论 / 与我的工作的关系 / 来源片段 id`。
- 卡片入库，可按卡片检索，可修改、可删除。
- 生成卡片时若没有可用模型（未配置模型 API），必须给出**明确提示**并允许
  用户手工填写，而不是静默产出空卡片。

### F4 复习队列与掌握度

- 卡片可以加入复习队列。
- 每次复习给出 0~5 的掌握度评分；系统据此计算下次复习时间
  （间隔重复算法：评分越高间隔越长，评分 0 则当天重来）。
- 队列展示：今天该复习的卡片、每张卡片的掌握度与下次复习时间。

### F5 记忆与跨会话复用（**PowerContext 承担**）

系统必须把下列内容作为**记忆**保存，并在**后续运行中读回并实际使用**：

| 记忆项 | 内容 | 后续如何使用 |
| --- | --- | --- |
| 用户画像 | 研究方向、常用标签、当前在写的综述主题 | 检索时自动作为过滤/加权条件；生成卡片时作为"我的工作"上下文 |
| 复习记录 | 每张卡片的评分历史、下次复习时间 | 下次打开时直接给出待复习清单，而不是空的队列 |
| 薄弱点 | 被评为低分的卡片所对应的标签/主题 | 主动提示"这些主题你不熟"，并优先推荐相关卡片 |

要求：
- 记忆**必须落盘**，进程重启后仍能读回（不是内存里的临时变量）。
- 读回的记忆必须**真的影响输出**（在结果、提示或推荐里可见），并在输出中
  **标明**哪些部分来自记忆。

### F6 综述提纲

按标签 / 年份 / 作者聚合已有卡片，输出一份结构化提纲（Markdown），
每条提纲后面附上支撑它的卡片（标题 + 出处）。

## 4. 技术硬约束

1. **必须使用 seekdb（或 OceanBase）**：文献块、卡片、检索索引都存在数据库里；
   检索必须是**数据库内的查询**（全文索引 + 结构化条件），不能在应用层
   把全表拉出来自己算匹配。评审会看执行计划，需要能看到原生索引被使用。
2. **必须使用 PowerContext**：F5 的记忆由 PowerContext 保存与读回。
   两者分工必须写清楚：**seekdb 存"资料"，PowerContext 存"关于你的记忆"**。
3. **必须有一个明确的调用入口**（CLI 即可），每个子命令说明输入与输出。
4. **必须有测试**：单元测试（不依赖数据库的部分）+ 端到端验证（依赖数据库）。
5. **不得提交真实凭据**：模型 API Key、数据库密码一律用占位值 + 环境变量。
6. **依赖与配置要齐全**：评审按运行说明从干净环境跑通，不能依赖未交付的本地文件。

### 技术选型倾向（可调整，但需说明理由）

- Python 3.11+，CLI 入口，`argparse` 或 `typer` 均可。
- 数据库访问用 `pymysql`（服务端模式，MySQL 协议）。
- PowerContext 用**进程内 Core SDK**（`powercontext.builtin.runtime.open_builtin_runtime`，
  SQLite 文件后端），不起 HTTP 服务——评审无需先跑服务。

## 5. 验收标准（必须全部满足）

| # | 验收项 | 判定方式 |
| --- | --- | --- |
| A1 | 能运行 | 干净环境按运行说明：装依赖 → 起数据库 → 导入样例 → 跑通全部命令 |
| A2 | seekdb 真的在参与 | 检索查询的执行计划出现原生索引扫描；查询记录里能看到实际 SQL |
| A3 | 中文检索有效 | 用中文关键词检索中文笔记，能命中正确的片段并给出正确出处 |
| A4 | 结构化过滤有效 | 年份/标签/作者的过滤与全文检索同时生效，且互不干扰 |
| A5 | PowerContext 真的在参与 | 记忆写入后重启进程，记忆能读回，且输出中可见其影响 |
| A6 | 跨会话复用 | 第二次运行 `review` 时，待复习清单里是上次的卡片（而不是空） |
| A7 | 卡片闭环 | 片段 → 卡片 → 加入队列 → 打分 → 下次复习时间被算出 |
| A8 | 导入幂等 | 重复导入不产生重复块；删除文件后重新导入，旧块消失 |
| A9 | 无凭据入库 | 仓库内不出现任何真实 Key / 密码 |
| A10 | 有网站 | Qoder Sites 上有可公开访问的站点，能看懂项目在做什么 |

```markdown
---
title: 论文标题
authors: 作者 A, 作者 B
year: 2024
tags: 对比学习, 图神经网络
---

# 论文标题

## 问题
……

## 方法
……

## 结论
……
```

样例覆盖：中英文混合、3 个不同年份、8 个标签、其中 2 篇是同一标签下的
「相关工作」（用于验证聚合与综述提纲）。

**样例数据是输入，不是期望输出**——具体检索结果、实现方式由 Qoder 决定，
但必须满足 A2~A8。
