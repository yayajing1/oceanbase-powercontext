# MiniMax 调用留档

每次调用 MiniMax 都会留下两个文件：

- `<task>_<时间戳>_answer.md`：本次请求的 **prompt 原文**、模型 **回答原文**、模型名、
  request id、耗时与 token 用量；多次尝试时每一轮都会单独记录。
- `<task>_<时间戳>.patch`：从回答中提取出来的 unified diff（应用前的原文）。

| 文件 | 结果 |
| --- | --- |
| `TASK-ORD-003_20261114-163554_*` | 模型只看到了函数片段，diff 的行号与真实文件对不上，**未应用**（`patch_error`） |
| `TASK-ORD-003_20261114-163809_*` | 输出预算被思考过程耗尽，回答被截断，**没有 diff** |
| `TASK-ORD-003_20261114-164050_*` | **成功**：补丁被应用，目标测试与回归测试全部通过 |
| `TASK-ORD-003_20261114-164421_*` | 补丁本身正确，但 hunk 行号偏移 1 行，当时尚未实现锚点搜索，**未应用** |
| `TASK-ORD-003_20261114-164744_*` | 成功（端到端验证的一次） |
| `TASK-ORD-003_20261114-165211_*` | 成功（最终 19/19 验证的一次） |

失败的几轮也保留在这里，因为它们是「迭代过程」的一部分：三次失败分别对应
「提示词缺少完整文件」「输出预算不足」「补丁锚点过严」三个问题，修复过程见
[`../minimax_development.md` §5](../minimax_development.md)。

> 这些文件里的 prompt 含规格与代码正文，但**不含任何凭据**：客户端在写盘前已把
> API Key 替换为 `***redacted***`。
